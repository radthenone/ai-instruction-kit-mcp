# S3-compatible storage

## Kiedy stosować

Object storage dla capability **files** — upload, miniatury, PDF, zdjęcia produktów.

Jeden adapter w kodzie obsługuje wszystkie backendi S3-compatible:

| Provider | Dev | Produkcja |
|----------|-----|-----------|
| MinIO | typowy lokalnie | — |
| AWS S3 | — | typowy prod |
| DigitalOcean Spaces, Cloudflare R2 | — | ten sam adapter, inne endpoint URL |

Profil projektu:

```yaml
decisions:
  storage: s3
```

## Konfiguracja

```text
STORAGE_BACKEND=s3
AWS_S3_ENDPOINT_URL=http://minio:9000    # MinIO dev; puste dla AWS
AWS_STORAGE_BUCKET_NAME=media
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
FILE_SCOPE_BUCKETS=products:media,avatars:media
```

Mapy scope → bucket w `core/settings/` — **nigdy** hardcode w app domenowej.

## Zasady architektury

- Adapter S3 tylko w `core/integrations/storage/providers/`
- App domenowa trzyma `file_id` (FK do `StoredFile`), nie `ImageField`
- MinIO dev = ten sam kod co AWS prod — różni się tylko env

## Powiązane

- `capability:files`
- `pattern:providers-and-settings`
