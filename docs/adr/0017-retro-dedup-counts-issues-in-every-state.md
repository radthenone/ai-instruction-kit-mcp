# Retro dedup counts issues in every state

ADR-0015 searched only open issues for the `<!-- retro-fingerprint: ... -->` marker, so a proposal came back as soon as its issue was closed, whether it was fixed or rejected. We decided that an issue carrying the marker silences the proposal in any state, open or closed, and that `kit-ai retro report` reads the full issue list with `gh api --paginate` instead of one capped `gh issue list` page. That endpoint also returns pull requests, so a marker copied into a PR body silences the proposal too, which is harmless. The alternative was to let issues closed as completed stop silencing, so that a returning finding would signal a regression. We rejected it because the retro cache never ages: findings recorded before the fix would come straight back as false regressions. Regression detection, for example by `kit_sha`, is left for a separate issue. Partly supersedes ADR-0015.
