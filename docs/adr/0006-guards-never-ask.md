# A Guard allows or denies, never asks

Every Guard the Bootstrap installs returns `allow` or `deny`. None returns `ask`, and the deny list is deliberately short: `git reset --hard`, `git clean -f`, force push and plain push to `main`/`master`/`dev`, `git branch -D`, `git checkout .` / `checkout --`, recursive `rm` on a broad path, writes into system directories (`~/.ssh`, `/etc`, `C:\Windows`, `Program Files`, `~/.claude/settings*.json`), and any access to secrets or hand-edits of lockfiles. Everything else passes, including `git stash`, `git restore`, `find -delete`, `rm -rf` inside the repo, and writes anywhere else in the home directory.

The previous set asked on six paths. In a Client's auto mode an `ask` from a hook blocks exactly like a permission prompt, so the agent stopped several times per session on `git stash` or `rm -r node_modules`, and the human answered each prompt without the context to judge it. A gate that asks is a gate the human learns to approve blindly. A short deny list the model can read (`permissionDecisionReason`) makes it pick a safe alternative instead.

The trade is real: a Bash command can now overwrite `~/.bashrc` or another repository's working tree without a prompt. We accept that because git recovers anything inside the repo, the Client's native permission still gates Edit/Write outside `cwd` and `additionalDirectories`, and the places where a mistake is not recoverable (keys, system configuration, the Client's own settings) stay on the deny list. Growing that list is cheap; reintroducing `ask` is the thing this decision rules out.
